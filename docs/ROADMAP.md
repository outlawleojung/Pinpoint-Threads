# 로드맵 — 개입을 줄이고, 자율 품질을 벌기

**북극성**: 사용자님이 매번 개입하지 않아도, 품질이 무인 신뢰 수준으로 돌아가는 시스템. (vision.md: 터진 글의 "왜 터졌나" 자율 재생산)

**핵심 원리**: 개입 ↔ 품질은 악순환. 품질이 낮아 개입하고, 개입 의존이라 자율 품질이 안 큼. **자율성은 품질로 번다.** 그래서 우선순위는 ① 사용자 개입을 직접 없애는 것 ② 품질을 올려 자율을 버는 것 순.

## 사용자님이 지금 매일 하는 개입 (제거 대상)

| 개입 | 유발 원인 | 없애는 항목 |
|---|---|---|
| dev·dev:worker·dev:bot 수동 재기동 | 로컬 개발 서버 · 앱 켜야 크론 돎 | T1 클라우드 배포 |
| 쇼핑마다 URL+상품명 직접 던짐 | 자동 매칭 불신 (오매칭 잦음) | T2 매칭 정확도 |
| 매 카드 승인/리젝 | 품질 게이트 · 무인 신뢰 부족 | T3 사전 자동 QA + 승인 티어링 |
| 엉뚱 상품·시나리오·미디어 누락 QA | 발행 전 결정적 검증 없음 | T3 사전 자동 QA |

## T1. 클라우드 배포 — 재기동 마찰 제거 (개입↓, 착수 쉬움)
- **왜**: 매일 3개 프로세스 수동 재기동 + "앱 켜야 크론 실행"이 가장 잦은 마찰. VPS 24시간 상시가동이면 재기동·크론 걱정 사라짐.
- **무엇**: AWS Lightsail Seoul($5 flat·하드캡X) 등에 배포. 결정만 나면 하루 작업.
- **막힌 것**: 사용자 결제 방식 결정 (하드캡 이슈). → **이거 하나만 정하면 즉시 진행.**
- **난이도**: 낮음(엔지니어링) · 결정 대기.

## T2. 매칭 정확도 — 상품명 손입력 제거 (개입↓, 최대 레버·난이도 높음)
- **왜**: 사용자님이 쇼핑마다 상품명을 직접 던지는 이유 = 자동 매칭을 못 믿어서. 이게 신뢰되면 → 던져둔 벤치마크/트렌드에서 **자동 소싱→매칭**, 손입력 사라짐.
- **무엇**: (a) 이미지 기반 매칭 강화 — 벤치마크 상품 이미지 vs 쿠팡 후보 이미지 Vision 대조 · 후보 랭킹. (b) 검색어 생성 품질(브랜드·모델 추출). (c) 실데이터로 매칭 정확도 측정 → 임계 넘으면 자동 소싱 재개.
- **정직한 한계**: 쿠팡 검색 순위는 우리 통제 밖. 100%는 불가. 하지만 지금(이름 유사도)보다 이미지 대조로 크게 개선 가능.
- **난이도**: 높음 · 실측 검증 필수 (이번 피드백 루프처럼).

## T3. 사전 자동 QA + 승인 티어링 — 승인·검수 부담↓ (개입↓)
- **왜**: 사용자님이 최종 QA(엉뚱 상품·시나리오·미디어·개인정보)를 하고 매 카드를 승인. 이걸 코드가 대신하면 "전건 승인" → "스팟체크".
- **무엇**: (a) 발행 전 결정적 자동 검증 — 상품 정합·미디어 2+·비디오/댓글 완결·개인정보·본문 링크(이미 있음) 통과 못하면 자동 리젝+재생성. (b) 저위험(검증 통과+과거 유사 성공)은 자동 승인, 고위험만 사용자 승인.
- **난이도**: 중 · T2 품질에 부분 의존.

## T4. 성과 피드백 루프 성숙 — 품질 자율 상승 (품질↑, 이번에 구축 완료)
- **상태**: 스코어러·스하리 학습·확산(본문조회 1만 절대) 구축·실측 검증 완료.
- **다음**: 데이터 축적 관찰 → 쇼핑 카피 학습 활성화(winner 표본 쌓이면) · 쿠팡 대시보드 클릭/전환으로 성과 판정 보정(프록시→실측).

## T5. 벤치마크 품질 게이팅 — 원본이 좋아야 카피도 좋음 (품질↑)
- **왜**: 트렌드-검색 자동 인제스트가 저품질 글을 담으면 카피도 저품질. 각색은 원본을 못 넘음.
- **무엇**: 인제스트 시 참여수·정합성·상품 명시 여부 필터 강화.
- **난이도**: 중.

## T6. Pipeline C 일상글 — 미착수 (확장)
- **왜**: 계획된 3파이프라인 중 하나 미착수. 사용자님이 "해외 귀여운 동물 등" URL 던질 예정.
- **무엇**: 소스 방식 확정 → 분류·카피·발행. 스하리/쇼핑 인프라 재사용.
- **난이도**: 중.

## T7. 스하리 팔로우백 (B4) — 미착수 (확장·리스크 주의)
- **무엇**: 하드캡 3~5/일 · 사용자 승인만(자동 X · 계정 정지 리스크). 로직 골격만 있음(TODO).
- **난이도**: 낮음(로직) · 안전 정책 준수 필수.

## 권장 순서 (개입 감소 체감 순)
1. **T1 배포** — 결제 방식만 정하면 즉시. 재기동 마찰 즉시 제거.
2. **T2 매칭 정확도** — 최대 레버. 실측 검증하며 제가 주도. 손입력 제거의 관문.
3. **T3 사전 QA + 승인 티어링** — 승인·검수 부담 제거.
4. 이후 T4~T7 는 데이터·품질 성숙에 따라.

## 이 로드맵 사용법
각 세션은 T1~T7 중 하나의 큰 덩어리를 잡아, 실측 검증하며 완주. 이 문서로 "할 일이 많다"는 혼돈을 관리.
