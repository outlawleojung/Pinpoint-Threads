# 수동 쇼핑 발행 흐름 — 상품명 기반 (확정)

## 목표
최소 개입으로 사용자가 던진 URL 을 5계정 쇼핑 콘텐츠로 발행.
사용자 개입 = **벤치마크 URL + 상품명(텍스트)** 딱 두 가지.

## 문제 배경 (왜 이 방식으로 정했나)
- **텔레그램이 쿠팡 링크(link.coupang.com·coupang.com) 전송을 차단** (타이핑해도). → 사용자가 딥링크·URL 을 직접 못 보냄.
- **상품번호만으론 쿠팡 딥링크 생성 불가**: 딥링크 API 가 itemId+vendorItemId 요구, 상품번호에서 추출 불가 (동적 로드·봇 차단).
- **자동 Product Matcher 는 오매칭 잦음**: AI 가 생성한 짧은 searchKeyword 로 검색 → 무관 상품 매칭 (vision-failed 다수).

## 해결: 상품명 검색 + Vision 매칭
- 상품명은 **링크가 아니라 텍스트** → 텔레그램 차단 회피.
- 쿠팡 파트너스 **검색 API** 에 사용자 상품명(전체) 넣으면 정확한 상품이 top 에 나옴 (실측 확인).
- 검색 결과의 productUrl(itemId 포함) → **딥링크 생성 성공**.
- 검색 top-N 후보를 **원본 벤치마크 이미지 vs 쿠팡 상품 이미지 Vision 비교** → 가장 유사한 것 자동 선택 + 유사도 점수.
- 승인 카드에 매칭 상품 이미지 + 원본 나란히 → 사용자가 육안 최종 확인 (오매칭 차단).

## 흐름
```
사용자 (텔레그램, 한 메시지):
  https://www.threads.com/@xxx/post/yyy      ← 벤치마크 URL (안 막힘)
  물없이 일회용 미니칫솔 퀵클린 애플민트향        ← 상품명 (텍스트 · 안 막힘)
        ↓
시스템:
  1. 벤치마크 URL 인제스트 (미디어·텍스트 추출 · 비디오 shortcode 매칭)
  2. 상품명으로 쿠팡 검색 top-N
  3. 각 후보를 원본 이미지와 Vision 비교 → best 선택 (+ 유사도)
  4. best 상품 딥링크 생성 + 전체 제목으로 특징 반영 카피
  5. 5계정 각색 → 승인 카드 (매칭 상품 이미지 병치)
        ↓
사용자: 승인/리젝 (오매칭이면 리젝)
```

## 폐기되는 것
- 대기 카드(pending-match) · 회신코드 방식 → 상품명 검색으로 매칭 실패 자체가 줄어듦 (백업으로만 유지)
- 사용자의 쿠팡 딥링크 수동 생성 → 불필요 (상품명만)
- 하이브리드 URL 답장 → 불필요

## 남은 한계 (정직하게)
- 상품명 검색도 유사 상품 섞임 (용량·버전 차이) → Vision 비교 + 사용자 육안 승인으로 방어. 100% 자동 아님.
- 완전 무개입 자동은 현 기술로 불가 (상품↔실사용 미디어 연결은 사람 판단 필요).
