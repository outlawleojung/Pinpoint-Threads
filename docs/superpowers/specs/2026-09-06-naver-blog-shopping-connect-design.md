# Pipeline D — 네이버 블로그 쇼핑커넥트 수익화

## 1. 목표

네이버 **쇼핑커넥트(성과형 제휴)** 로 잘 팔리는 스마트스토어 상품을 골라, SEO 최적화된
고품질 블로그 원고를 **상품 우선(product-first)** 으로 생산한다. 쓰레드 파이프라인(A/B/C)과는
**별개 파이프라인**으로 운영한다.

핵심 철학은 기존과 동일: 자동화가 아니라 "왜 잘 팔리고 왜 상위노출되는가"를 AI가 원고 품질로
재현하는 것. 발행 순위는 축적으로 오른다(아래 C-Rank 참조).

## 2. 배경 · API 현실 (검증됨)

- **네이버 블로그 글쓰기 API = 2020년 5월 종료.** 종료 사유가 정확히 "제휴/광고성 글 API 대량 발행"
  차단이었음 → 재개 없음. ([뉴시스](https://www.newsis.com/view/NISX20200413_0000992012))
  → **자동 발행 불가. 발행은 사용자 수동 복붙이 유일한 안전 경로.** 브라우저 자동 발행은 네이버가
  명시적으로 적대시하는 패턴이라 계정 정지 리스크 최상 → **금지** (CLAUDE.md 자동화 금지 원칙과 일치).
- **쇼핑커넥트** = 크리에이터가 등록된 스마트스토어 상품을 골라 **전용 제휴 링크 발급** → 구매 발생 시
  수수료. 링크는 **스마트스토어 상품 페이지로 연결** → 상품 이미지·스펙 자동 취득 가능.
- 읽기용 공식 API는 있음: **쇼핑검색 API**(상품 조회), 블로그검색 API.
- 브랜드커넥트 상품목록/판매랭킹 공식 API = **없음** → "잘 팔리는 상품" 선택은 사용자 수동.

## 3. 범위

**포함**
- 상품 수동 유입(텔레그램) → 상품 데이터 보강 → 이미지 확보 → SEO 원고 생성 → 승인 카드 → 수동 발행 산출물
- 원고 SEO 스키마(제목/도입/본문/소제목/이미지 배치/태그/공정위 문구)
- 이미지 자동 취득(스마트스토어) + Gemini 보조 이미지 생성
- 블로그 운영 규칙(C-Rank 대응: 1주제 집중, cadence, 정보:제휴 비율)

**제외 (명시)**
- 자동 발행(불가) · 브라우저 자동 로그인/발행(금지)
- 브랜드커넥트 협찬 캠페인 소재 흐름 (초기 제외, 성과형만)
- 순위/상위노출 "보장" (C-Rank·D.I.A.는 계정 히스토리·독자 반응에 좌우 → 통제 불가)

## 4. 파이프라인 흐름

```
[1] 사용자 → 텔레그램(기존 봇 1개, 전용 커맨드 /naver <커넥트링크> + 선택 메모)
        ↓
[2] 링크 해석 → 스마트스토어 상품 식별 (productId/상품명)
        ↓
[3] 상품 데이터 보강: 쇼핑검색 API(가격·스펙·경쟁제품) + 상세페이지(고화질 상품컷)
        ↓
[4] 이미지 확보: ① 공식 상품 이미지(자동) + ② Gemini 보조 이미지(썸네일/비교그래픽)
        ↓
[5] Copywriter(Sonnet): SEO 스키마대로 원고 생성 + 이미지 배치 지점 표기
        ↓
[6] 승인 알림 = 텔레그램 (제목·요약·Admin 발행 페이지 링크)
        ↓
[7] 사용자 승인 → Admin "발행 페이지" 생성 (블록 단위 복사 + 이미지 순서/삽입 위치 가이드)
        ↓
[8] 사용자가 네이버 에디터에 블록별 붙여넣기 → 제목/소제목 스타일 수동 지정 → 이미지 삽입 → 발행
```

**채널 주의**: 텔레그램 봇은 기존 것 1개를 그대로 사용하되, 쓰레드 흐름과 섞이지 않게 `/naver`
전용 커맨드로 분기한다. 사용자는 텔레그램에서 글을 직접 쓰지 않는다 — 링크만 보내고, 원고는
시스템(Sonnet)이 생성한다.

**발행 UX 현실 (검증됨)**: 네이버 스마트에디터 원은 **마크다운 미지원**(`#` 안 먹음), HTML 붙여넣기도
서식이 완전히 유지되지 않는다. 제목/소제목은 에디터의 "제목1/제목2" 스타일을 **수동 지정**해야 한다.
([근거](https://sahyo123.com/entry/네이버-블로그에서-마크다운-문법-적용하는-법))
→ 따라서 "원클릭 완벽 복붙"은 불가능. 대신 Admin 발행 페이지가 **블록 단위 복사 + 소제목 스타일
라벨("여기는 제목2") + 이미지 삽입 위치 지시**를 제공해 템플릿이 어긋나지 않도록 안내한다.
실제 발행은 에디터에서 3~5분 손작업(스타일 지정 + 이미지 끼우기)이 남는다.

## 5. 원고 SEO 스키마 (D.I.A. = 문서 품질)

시스템이 매 편 산출하는 결정론적 슬롯. (근거: 2026 네이버 SEO 데이터)

| 슬롯 | 최적화 규칙 |
|---|---|
| 제목 | ≤80자, 핵심 키워드 맨 앞, 숫자/질문형 변형 |
| 도입 첫 200자 | 결론·핵심 키워드 먼저 (초반 가중 + 체류 60초↑ 유도) |
| 본문 | 2,000~2,500자, 모바일 2~3줄 단락 |
| 소제목 | H2/H3, ~15자, 질문형/번호, 키워드 포함 |
| 이미지 | 5~10장, 3~5단락마다 1장, 각 지점에 "무슨 이미지" 캡션 |
| 경험 서술 | 실사용·비교·후기형 구체 정보 (D.I.A. 핵심) |
| 커넥트 링크 | 본문 자연 삽입, **첫 제휴 링크 직전 공정위 안내 문구** |
| 태그 | 연관검색어/자동완성 기반 롱테일 10개 |

## 6. 블로그 운영 규칙 (C-Rank = 블로그 신뢰도)

C-Rank는 주제 일관성·누적을 평가 → 원고 한 편이 아니라 운영 방식이 순위를 만든다.

- **1 블로그 = 1 주제군** (기본값, 스펙 리뷰 시 확정). 잡블로그 지양.
- **cadence 주 3~4회** (기본값). 원고 재고를 미리 축적해 규칙 발행.
- **정보성 : 제휴 = 7 : 3** (기본값). 순수 정보글도 시스템이 생성 → "광고 블로그" 저품질 회피.
- 공정위 제휴 문구 필수 (첫 제휴 링크 전, 독자가 쉽게 보는 위치).

## 7. 이미지 전략

| 종류 | 소스 | 비고 |
|---|---|---|
| 상품 실물 | 스마트스토어 상품페이지 자동 취득(공식 이미지) | AI 생성 금지(실물 불일치·SynthID 감지·기만) |
| 보조·정보성 | Gemini(Nano Banana) 자동 생성 | 썸네일·개념 일러스트·비교 그래픽 |
| (선택) 사용자 실사진 | 텔레그램 첨부 | 있으면 원본성 가점 |

- **SynthID 유의**: AI 이미지에 워터마크 내장 → 한 편을 AI 이미지로 도배 금지. 공식 상품 이미지와 혼합.
- 새 의존성: **Gemini API** (이미지 전용 병행. 원고 생성은 기존 Anthropic Claude 유지).

## 8. 시스템 통합

**재사용 (기존 모듈)**
- copywriter (Sonnet) — 네이버용 프롬프트/스키마 추가
- approval-gate / 기존 grammY 봇 (1개) — `/naver` 전용 커맨드로 분기, 수동 쇼핑 흐름과 동일 철학
- media-handler / Cloudinary — 이미지 저장·번들
- Admin UI — 발행 페이지 라우트 추가 (기존 세션/DB 인프라 재사용)
- 쇼핑검색 API 어댑터 (신규지만 기존 커머스 어댑터 패턴 재사용)

**신규**
- `smartstore-fetcher` — 쇼핑커넥트 링크 해석 + 상품페이지 이미지/스펙 취득
- `gemini-image` 어댑터 — 보조 이미지 생성
- `naver-copywriter` 프롬프트 — SEO 스키마 산출
- **Admin 발행 페이지** — 블록 단위 복사 버튼 + 소제목 스타일 라벨 + 이미지 순서/삽입 위치 가이드
  + 순서대로 이미지 다운로드. (텔레그램은 승인 알림 + 이 페이지 링크만 전달)
- 원고 패키지 export (블록 구조 텍스트 + 이미지 번들; HTML 변환본은 옵션)

**데이터 모델 (초안, 스펙 리뷰 후 확정)**
- 기존 `Post.kind` 에 `NAVER_BLOG` 추가 **또는** 별도 모델 `NaverPost` (별개 파이프라인이므로 후자 유력)
- `NaverProduct` (쇼핑커넥트 상품: productId, 커넥트링크, 가격/스펙 캐시, 이미지 URL[])
- 블로그 주제·cadence·재고 관리용 경량 스케줄 상태

## 9. 미결정 · 권고 기본값 (스펙 리뷰에서 확정)

1. 블로그 개수·주제 → 기본값: **1개·단일 주제**
2. cadence → 기본값: **주 3~4회**
3. 정보:제휴 비율 → 기본값: **7:3**
4. 데이터 모델 → `NaverPost` 별도 모델 (유력) vs `Post.kind` 확장

## 10. 리스크

- **저품질(광고성) 판정**: 네이버가 API를 죽인 이유. → 정보성 비율·원본성·구체 경험으로 완화가 핵심.
- **스마트스토어 스크래핑 취약성**: 구조 변동·차단 → 쇼핑검색 API 우선, 상세 스크래핑은 폴백.
- **AI 이미지 감지(SynthID)**: 보조 이미지 비중 관리.
- **순위 불확실성**: 상위노출 보장 불가 — 축적 전략으로만 상승.
