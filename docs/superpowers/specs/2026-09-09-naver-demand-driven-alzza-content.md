# 네이버 실수요 기반 알짜 콘텐츠 생성 — 설계

**작성:** 2026-09-09 · Pipeline D (깜냥로그)

## 왜 (문제 정의)

지금 생성 글의 실패 원인은 **문체가 아니라 "무엇을 쓰느냐"의 출처**였다.
- 주제·앵글이 실수요가 아니라 **상상/LLM 탄젠트**에서 나옴 → 뻔하거나(1차) 과도하게 학술적(2차).
- 실측: `레트로 유리그릇`은 자동완성 1개(수요 없음). 반면 사람들은 `유리그릇 버리는법`, `전자레인지 깨짐/뚜껑 여는법`, `다이소 유리그릇`, `빈티지 그릇 어디서 사나`를 실제로 검색.
- 즉 **"찾는 질문"에 **"남다른 깊이"**로 답해야 알짜**가 된다. (유튜브 전략과 동일: 대중 관심사 ∩ 내가 쓸 수 있는 것)

## 목표

주제·앵글을 **네이버 자동완성 실수요**에서 뽑고, **알짜 깊이**(구체·메커니즘·착각 교정·결정 규칙)로 쓰되, **생활 독자 눈높이**(과도한 학술 금지)에 맞추고, **사실 오류를 걸러내는** 생성 파이프라인.

## 파이프라인 (5단계)

### 1. 실수요 수집 (demand harvest)
- 입력: 표준 카테고리(5개) 또는 시드 키워드.
- `fetchAutocomplete` **2-hop 확장**: 시드 → 자동완성 → 상위 항목 재조회로 롱테일 질문까지. (예: `유리그릇` → `유리그릇 전자레인지` → `유리그릇 전자레인지 깨짐`)
- 결과: 실제 쿼리 풀. **문제/질문형 쿼리 가중**(버리는법, 깨짐, 되나요, 여는법, 추천, 어디서) — 정보 니즈가 뚜렷한 신호.

### 2. 주제 선정 (demand → topic)
- 풀에서 **날카로운 쿼리 1개(또는 밀접 클러스터)** 선택. 넓은 나열 금지.
- **수요 없는 쿼리 배제**(자동완성 빈약 = skip). 최근 발행분과 dedup.
- 선정 쿼리 = "사람들이 실제로 치는 질문" = 글의 축.
- **의도 라우팅**: 상품 연결성 있으면 AFFILIATE 성향(예: 다이소/추천/어디서), 순수 정보면 INFO(예: 버리는법/분리수거).

### 3. 알짜 생성 — 2패스
- **패스 1 (초안)**: 알짜 시스템 프롬프트. 선정 쿼리에 직답.
  - 강제: 구체 수치·기준·명칭 / "왜"(메커니즘) / 상황별 결정 규칙 / 흔한 착각 교정 / 각 소제목 "검색 1페이지엔 없는 한 방".
  - 금지: 원론("용도를 정하세요"), 근거 없는 뭉뚱그림, 헤지("~수도"), 가짜 1인칭("저도 그랬어요/저처럼 실수하지"), 모든 문단 동일 구조.
  - 출력: **기존 JSON 스키마 유지**(title/intro/sections/imageSlots/tags/category/productHint).
- **패스 2 (자기비평 재작성)**: "검색하면 다 나오는 문장 / 근거 없는 뭉뚱그림 / 상투구 제거, 밀도↑".
  - **깊이 보정 가드**(중요): 과도한 학술·전문용어 나열 금지. **생활 독자가 바로 써먹을 실용 수준**으로. (파괴역학·응력확대계수식 과잉 방지)

### 4. 사실 검증 패스 (fact-check)
- 구체 주장(수치·연도·용어)을 훑어 **확실치 않으면 단정하지 말고 일반 표현으로 낮추거나 삭제**. 틀릴 위험 있는 구체값은 검증 가능한 것만 남김.
- 기본은 "완화(soften)" 방식(외부 검증 없이 위험 축소).
- **옵션(후속)**: `WebSearch`로 핵심 주장 실검증 — 비용↑, 신뢰도↑. 초기엔 off, 필요 시 켠다.

### 5. 톤·출력
- 톤: 공감·문제해결형([[feedback_naver_engaging_not_dry]]) 유지하되 **가짜 1인칭 상투구는 뺀다**. 알짜 깊이 + 읽기 쉬움 + 실용.
- 출력·후단(publish-package, admin 발행페이지, 카테고리 뱃지, 소제목별 productHint, /naver·/naverlink)은 **그대로**. 생성 내부만 교체.

## 비용

글당 LLM 호출 3회(초안·비평·팩트체크) + 자동완성 수 회. 품질 우선이므로 수용. (팩트체크 WebSearch 옵션 시 추가)

## 범위 밖 (지금 안 함)

- 지식iN·카페 실제 Q&A 스크래핑: 네이버가 fetch 차단 + 자동화 리스크(CLAUDE.md) → 제외. **자동완성이 실수요 프록시.** (후속에 승인된 수단 생기면 검토)
- 검색광고 키워드도구(월간검색량): 계정·키 필요 → 후속.
- 발행 자동화: 계속 **수동**.

## 기존 17개 처리

새 파이프라인 가동 후: **실수요 있는 주제만** 재생성/유지, 수요 없는 주제(예: 레트로 유리그릇 고르기)는 실수요 쿼리로 **주제 교체** 후 재생성. 컨셉 밖(뷰티·USB) 2개는 별도 판단.
