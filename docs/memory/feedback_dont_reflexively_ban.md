사용자가 "이거 좀 과하다/똑같다"고 **관찰**하면, 그건 대개 "그 단어·요소를 금지하라"가 아니라 **"자연스럽고 다양하게 만들어라"**는 품질 요청이다. 관찰을 명령으로 오독해 프롬프트에 "○○ 금지" 규칙을 반사적으로 박지 마라.

**Why:** 사용자 지적 — "내가 그렇게 말했다고 금지를 시키라는 게 아니라고, 왜 내가 무슨 말만 하면 다 금지야?" (실화냐 남발 지적에 즉시 '실화냐 금지' 규칙 박은 것). 이번 세션에 소장각·동전·스하리·실화냐 등 반복적으로 관찰→금지로 변환함. **금지를 쌓을수록 카피가 위축돼 밍밍해진다**(스하리 vibe-mood로 망친 사례가 증거). [[feedback_controversy_drives_engagement]]처럼 '오류'라고 다듬다 훅을 죽인 것과 같은 실수.

**How to apply:** ① 관찰의 진짜 의도를 한 줄로 확인/추론(다양성? 톤? 특정 오류?). ② 금지어 목록 추가는 최후수단 — 대개는 "다양하게 써라" 정도의 품질 지시나, 아예 코드 변경 없이 넘어가는 게 맞다. ③ 하드 금지는 사용자가 명시적으로 "이건 하지 마"라고 할 때만. 관련 [[feedback_no_narrow_interpretation]] [[feedback_no_silent_stopgap]].
