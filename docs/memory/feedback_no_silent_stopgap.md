임시방편("추후 구현", "일단 1개만" 등)을 코드에 넣고 사용자 확인 없이 방치하지 말 것.

**Why:**
반복 사고: 수동 상품명 발행을 "일단 첫 계정만 · 다계정은 추후"로 임시 구현해놓고 방치 → 사용자가 정한 목표("각 계정에 맞게 5계정 자동 발행")를 어김 → "왜 자꾸 같은 계정에 발행하냐", "같은 실수 왜 반복하냐" 반복 질책. 사용자는 세션 초반에 이미 5계정 확산·계정별 시차를 명확히 지시했음.

**How to apply:**
- 원래 합의된 목표대로 완전히 구현. 부득이 축소하면 그 자리에서 사용자에게 명시적으로 알리고 확인받기.
- 코드에 "TODO/추후/임시" 남길 때는 사용자에게 반드시 구두 보고. 조용히 넣지 말 것.
- 상품 카피는 (1) 원본 벤치마크 내용 (2) 상품의 실제 핵심 특징 (예: 양말이면 "바닥 쿠션") 을 반드시 반영. 상품명만 보고 일반적 카피 금지.
- **새 경로·기능 만들 때 기존 정책(성별 필터·중복 방지·시차·공정위 문구 등)을 반드시 재사용.** 새로 짜면서 기존 정책 누락 금지. 예: 수동 상품명 발행을 만들며 기존 Account.audienceGender 성별 필터를 빠뜨려 남성 계정에 여성 상품 발행됨. "새 정책 반영하면 이전 정책 삭제하냐"는 질책 반복.
