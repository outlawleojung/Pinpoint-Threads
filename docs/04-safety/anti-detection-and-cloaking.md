# 안티 디텍션 및 클로킹 전략 (Anti-Detection & Cloaking Strategy)

본 문서는 Meta(Threads/Instagram)의 스팸 필터링, 계정 정지(Shadowban/Chain Ban) 리스크를 회피하고, 어필리에이트 링크의 유효 노출을 보장하기 위한 기술적 우회 방안 및 아키텍처 설계를 다룹니다.

---

## 1. 배경 및 핵심 위협 요인

일반적인 마케팅 자동화 봇이 플랫폼에서 정지당하는 이유는 크게 네 가지입니다:
1. **스팸 도메인 직접 노출**: 알려진 어필리에이트 도메인(`link.coupang.com` 등) 사용으로 인한 도달률 강제 제한(Shadowban).
2. **조직적 기기/IP 감지 (CIB)**: 하나의 서버 IP 및 기기 정보(Fingerprint)로 여러 계정을 동시에 운영하여 전체 계정이 묶여 정지당함(Chain Ban).
3. **중복 미디어 해시 필터링**: 동일한 이미지 바이너리(MD5 해시 등)가 여러 계정에서 반복 업로드되어 저작권 필터 또는 스팸 봇으로 자동 탐지됨.
4. **데드링크(Dead Link)로 인한 이탈**: 상품이 품절되거나 단종되었음에도 과거 콘텐츠에 링크가 그대로 남아 트래픽이 유실됨.

이러한 위협 요인들을 무력화하기 위한 실전 아키텍처 세부 우회 전략을 다음과 같이 수립합니다.

---

## 2. 세부 위협별 우회 기술

### 2.1 위협 1: 쿠팡 아웃링크 직접 노출 및 섀도우밴
*   **현상**: Threads 피드 및 대댓글에 쿠팡 파트너스 링크가 그대로 들어가면 메타 알고리즘에 의해 추천 피드 주입이 원천 차단됩니다.
*   **해결책: 클로킹(Cloaking) 및 개인 단축 URL 브릿지 서버 구축**
    *   **도메인 파편화**: 고유 브랜드 도메인(예: `my-style-trend.shop/link-id`)을 여러 개 확보하여 아웃링크로 사용합니다.
    *   **접속자 분석 필터링 (클로킹)**: 브릿지 서버로 들어오는 HTTP Request의 `User-Agent`, `IP 대역`, `Behavior 패턴`을 실시간 분석합니다.
        *   **Meta 검사 봇(FacebookExternalHit 등)**: 정상적인 패션 정보 블로그 포스트나 안전한 랜딩 페이지를 보여줍니다.
        *   **실제 인간 유저(Mobile UA 등)**: 302 Redirect를 통해 쿠팡 파트너스 최종 개인 딥링크로 자동 전환해 줍니다.
    *   이를 통해 플랫폼 보안 봇의 자동 차단을 회피하면서 실제 사용자에게만 구매 페이지를 정상 노출합니다.

### 2.2 위협 2: 다계정 동일 IP 및 기기 정보 감지 (CIB)
*   **현상**: 단일 로컬 서버 또는 단일 VPS(Hetzner 등)의 IP에서 4~5개 계정의 Access Token 발행 및 포스팅 요청이 집중되면 연대 보증 정지를 당합니다.
*   **해결책: 주거용 고정 IP 프록시 격리 및 디바이스 핑거프린트 다변화**
    *   **계정별 프록시 고정**: 각 계정(Persona 1~5)마다 고유한 **주거용 고정 IP 프록시(Static Residential Proxy)**를 매핑하여 `threads-client.ts`의 HTTP 클라이언트에 주입합니다.
    *   **디바이스 프로필 다변화**: API 요청 시 HTTP 헤더에 들어가는 `User-Agent`, `Accept-Language`, `Sec-Ch-Ua` 등의 기기 식별 정보를 계정마다 무작위가 아닌 고유하고 정합성 있는 모바일 디바이스(예: iPhone 15 Pro, Galaxy S24 등) 모델로 고정하여 격리합니다.

### 2.3 위협 3: 이미지 해시 감지 및 저작권 침해
*   **현상**: 타인 포스트나 쇼핑몰 사진을 가공 없이 업로드하면, 메타 서버가 파일의 MD5/SHA 해시값을 대조하여 중복 콘텐츠로 자동 낙인찍고 노출을 제한합니다.
*   **해결책: 미디어 미세 가공(Image Alteration) 엔진 구축**
    *   [media-handler](file:///Users/leones/Documents/Dev/Pinpoint-Threads/src/modules/shared/media-handler.ts)에 이미지 가공 파이프라인(Sharp 라이브러리 활용)을 연동합니다.
    *   수집한 이미지를 Threads에 올리기 직전 아래 조치를 자동 적용하여 **바이너리 해시값을 완전히 무작위화**합니다:
        1. 이미지 외곽 1~2% 미세 크롭(Crop).
        2. 밝기(Brightness) 및 대비(Contrast)를 인간이 인지할 수 없는 수준(0.5% ~ 1%)으로 미세 무작위 조정.
        3. 상황에 따라 이미지 좌우 반전(Horizontal Flip).
        4. 투명도 99%의 보이지 않는 미세 워터마크나 노이즈 주입.
    *   이 작업을 거치면 플랫폼은 해당 미디어를 '완전히 새로 생성된 고유 창작물'로 인식하게 됩니다.

### 2.4 위협 4: 품절 및 가격 변동으로 인한 데드링크(Dead Link)
*   **현상**: 도달이 급증하여 터진 골든 타임 포스트의 쿠팡 상품이 일시 품절되거나 터무니없이 비싼 타 판매자 제품으로 대체되어 전환율이 무너집니다.
*   **해결책: 실시간 동적 리다이렉트(Dynamic Redirect) 및 헬스 체크**
    *   **중앙 링크 관리**: 발행 시 단축 URL 브릿지 서버 DB에 해당 포스트 ID와 타겟 쿠팡 상품 ID를 매핑해 둡니다.
    *   **실시간 모니터링**: 백그라운드 워커가 일정 주기(예: 6시간 마다)로 활성 포스트들의 매칭 상품 품절 여부를 쿠팡 API로 확인합니다.
    *   **즉시 우회 리다이렉트**: 품절 또는 평점 기준 미달 발생 시, 사용자가 글을 직접 수정할 필요 없이 브릿지 서버의 리다이렉션 목적지를 **동일 스펙의 최저가/품절 임박이 아닌 다른 판매자 링크로 실시간 갱신**합니다.

## 3. 아키텍처 반영 로드맵

| 모듈 | 변경 예정 사항 | 우선순위 |
|---|---|---|
| `shared/media-handler` | Sharp 이미지 가공 파이프라인 (크롭, 미세 대비 조정) 탑재 | High |

| `bridge-server` (신규) | 클로킹 탐지 필터 및 동적 리다이렉트 DB 연동 API 구축 | Medium |
