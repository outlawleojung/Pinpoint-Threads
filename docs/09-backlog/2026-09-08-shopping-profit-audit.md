# 쇼핑 콘텐츠 수익성 진단

판단: 콘텐츠 우선 Line A에 집중하되, 좋은 원본의 매력 보존·정확한 상품 연결·실수익 측정을 함께 개선해야 한다. 신규 소싱/계정 확대보다 이 세 가지가 먼저다. 스하리는 별도 목적이며 쇼핑 전환 단계로 계산하지 않는다.

## 검증 범위와 한계

- 현재 코드, DB 읽기 전용 조회, 최근 쇼핑 발행 12건의 원문/생성문/상품/미디어 유무, 전체 발행 집계와 72시간 성과 확인.
- DB 쇼핑 PUBLISHED 13건: 2026-09-01~09-04. 72시간 스냅샷 11건: 합산 조회 3,991, 중앙값 41, 최고 3,359. 최고 한 건이 합산 조회의 약 84.2%. 테스트/재발행 가능성이 있는 운영 표본으로, 시장 전체 성공률로 일반화하지 않는다.
- 13건 중 threadsReplyId 없는 기록 2건. 플랫폼에서 현재 댓글이 없는지, 수동 복구됐는지, 삭제됐는지는 확인하지 않음.
- 모두 9월 8일 카피 지침 변경 전 발행. 새 지침 효과는 미검증.
- 이번 점검에서 원본 영상 전체나 쿠팡 실적/수익 리포트를 직접 보지 않았다. 주문·확정 수수료·클릭률·순이익은 미확인. 본문/댓글 조회는 서로 독립적으로 노출될 수 있어 그 비율을 실제 순차 퍼널 전환율로 보지 않는다.
- 현재 발행이 적은 원인을 문구 하나로 확정하지 않는다. 미디어·원본 선정·노출 대상·시점·상품 등 혼재.

결론: '한국말이 어색함'만의 문제가 아니다. 구체적인 사건/외형/감정을 범용 효용 설명으로 바꾸고, 한국화 과정에서 새로운 체험을 만든 사례가 존재한다. 그러나 슬리퍼처럼 범용 문구에서도 상대적 성과가 나온 만큼 문구만 원인으로 단정하지 않는다.

## 개선 우선순위

### 1. 장면을 제대로 이해하고 성공 포인트를 보존

근거: src/modules/pipeline-a/orchestrator.ts는 카피에 원문과 이미지 최대 1장 전달. 첫 비디오의 0초 JPG 폴백도 URL의 /video/upload/ 문자열 때문에 최종 카피 입력에서 제외될 수 있음. 영상 전개/소리/자막 설명 없음.

개선: 대표 프레임 여러 장 + 핵심 동작/결과 + 필요한 화면 글자를 짧은 구조화 자료로 생성. 직접 확인한 것과 원문 주장, 모르는 것을 구분. 같은 자료를 본문·댓글·상품 매칭이 공유. 사용자가 이미 미디어 설명을 주면 이를 우선 활용해 비용 절약.

예: 보호대의 정지 사진만 보면 '금속 손가락 도구'지만 실제 칼질 동작을 보면 '손 베일까 겁나는 상황'을 잡을 수 있다. 본문 후보는 공감/관찰/변화 등 서로 다른 포인트로 2~3개만 만들고 기본 1개를 추천. 선택 버튼을 늘려 사용자 검수 노동을 키우지 않는다.

### 2. 원본 영상이 사라진 채 승인되는 경로 차단

근거: video-rescue.ts는 사용자가 비디오 있음을 명시해도 재시도 실패 시 image-only 반환. handleMedia는 개수 2개 이상만 검사. 개수를 만족했다고 원본의 볼거리를 보존한 것은 아님.

개선: 원본에 영상이 필수인 경우 확보 실패를 '콘텐츠 미완성'으로 표시. 복구하거나 사용자가 대체 미디어를 확인하기 전 정상 완성품으로 취급하지 않음. 미디어 2개 하드룰은 유지하며 2번째 소재는 핵심 결과/다른 각도 등 의미 있는 것으로 선택. 영상 단독 발행으로 규칙을 우회하지 않음.

### 3. 구매할 상품이 영상 속 대상과 일치하는지 확인

근거: productNameHint가 있으면 trustKeyword=true. matcher는 상위 3개 검색 결과에서 이름 토큰 유사도로 선택하며 이미지 검증을 건너뜀. DB visionMatchScore는 직접 URL/과거 경로에서도 1일 수 있어 실제 시각적 동일성 증명이 아님. canonical productId URL만 구성하므로 최종 선택 옵션까지 확인할 필요가 있음.

개선: 상품명을 신뢰하되 검색 결과를 무조건 신뢰하지 않음. 소재의 핵심인 형태·색·모델·사용 방식 대조. 정확 일치/유사 대안/불명 구분. 대안이면 '영상 속 동일 제품'처럼 표현하지 않고 차이를 표시. 발행 직전 실제 도착 페이지의 상품·옵션·가격·배송·재고 확인을 가능한 범위에서 수행. 확인 불가능하면 불명으로 남김.

경제적 의미: 콘텐츠에서 기대한 것과 상세페이지가 다르면 확보한 클릭을 잃는다. 높은 가격/수수료만 따라 원본과 다른 상품으로 연결하면 실수익이 오히려 낮아질 수 있음.

### 4. 본문과 제휴 댓글을 하나의 콘텐츠로 검수

근거: reply-composer는 아직 '이거 없이 어떻게 살았는지', '아침 준비 시간 반 줄었음' 같은 체험/효능 예시 사용. 원본 미디어를 받지 않고 본문과 상품명으로 별도 생성. 실제 바디오일 댓글은 '향수보다 오래가더라'라고 쓰였으나 조회한 원문에는 지속력 비교가 없음.

개선: 새 본문 지침과 정합화하고 동일 장면 근거 전달. 본문은 시선·감정을 잡고 댓글은 연결한 상품이 무엇인지 혼동 없이 알리는 짧은 안내 역할을 실험. 모든 상품에서 구매 명령이나 가격을 넣자는 뜻은 아님. [광고]·제휴 문구 유지. 근거 없는 효과·체험·비교를 본문과 댓글 함께 검사. 댓글 누락은 본문 재발행보다 댓글만 복구하는 경로 우선.

### 5. 성공 지표와 학습을 쇼핑 수익에 연결

근거: scorer는 댓글 조회 없으면 본문 조회로 대체한 후 같은 풀에서 순위 계산. 합성 데이터로 실제 classifyPool 실행: 댓글조회 10,10,10,10,20인 글과 댓글미수집/본문조회 1,000인 글을 비교했더니 마지막 글이 winner. 측정 누락이 이점이 되는 오류를 재현함. 현재 72h 11건은 모두 댓글조회가 있어 이 특정 오류가 그 집계에 나타났다는 뜻은 아님.

개선: 본문 조회/댓글 조회/링크 방문/확정 수수료 각각 별도 지표. 같은 관찰기간끼리 비교. 누락은 미확인, 0으로 대체하거나 다른 단위와 혼합하지 않음.

현재 propagation은 24h와 72h 모두 본문조회 10,000 이상 요구. 24h=8,000, 72h=30,000이면 제외되며 3,359조회에서도 수익이 좋을 수 있음. 조회 기준은 탐색 신호로 쓰고 수익 검증 시 우선도를 보완하는 방향을 제안. 기존 사용자 확정 기준을 이번 감사에서 변경하지 않음.

쇼핑 RAG는 minLikes=500으로 조회하며 contentType 필터를 전달하지 않아 SHARING/DAILY 혼입 가능. 실제 혼입 여부는 미확인. copy-learning.ts의 능동 요인학습은 스하리 전용. 쇼핑은 성공 원본의 장면/반응과 국내 결과를 축적하고, 콘텐츠 유형을 분리한 뒤 사용자가 선택한 좋은 한국어 카피를 참고하는 편이 맞음.

### 6. 최소한의 수익 장부와 실험 이력

현재 Post 스키마에 실제 클릭/주문/확정 수수료/제작 시간/프롬프트 버전 필드가 없음. LLM 토큰은 로그에 남지만 게시물별 원가/재생성 비용으로 합산하지 않음. 수익 리포트 연동을 완료할 때까지 기다리지 말고, 내보낸 리포트나 수동 기록으로 시작 가능.

기록: 게시물 ID, 원본, 선택 포인트, 미디어 구성, 상품·옵션, 발행 링크/제휴 링크 ID, 프롬프트·모델 버전, 생성/수정 시간, 24/72h 조회, 실제 링크 방문(가능한 범위), 주문/취소/확정 수수료, 변동 비용.

리포트가 게시물별 매핑을 지원하지 않으면 계정/캠페인/기간 단위임을 표시. 같은 상품을 산 매출과 해당 유입에 귀속된 다른 상품 구매 실적도 리포트가 제공하는 범위에서 구분. 매칭되지 않는 매출을 특정 글의 성과로 만들지 않음.

Meta 공식 문서는 게시물/프로필 링크 방문 Insights를 설명한다. 현재 클라이언트는 views/likes/replies/reposts/quotes만 요청. 앱 UI에서 실제로 볼 수 있는 범위부터 확인하고 API 또는 댓글별 지원은 별도 검증해야 함.

## 가상 수익 시뮬레이션

모든 수치는 가정이며 실제 쿠팡 수수료율/프로젝트 실적 추정치가 아님. AI로 추천 알고리즘 노출을 예측한 결과도 아님.

공헌이익 = 조회수 × 실제 링크 방문율 × 방문당 확정 수수료(EPC) − 게시물별 비용.
EPC는 해당 클릭 집단의 귀속된 확정 수수료/클릭수. 광고한 상품 단가만으로 계산하지 않는다. 기간/귀속 기준이 다른 집계는 혼합하지 않음.

게시물별 비용 3,000원 가정: 직접 변동비 500원 + 사용자 작업 10분 × 시간가치 15,000원/시간 = 2,500원. 월 고정비와 세금은 별도이며 표의 이익은 순이익이 아님.

| 시나리오 | 조회 | 링크 방문율 | 방문 수 | EPC | 수수료 | 비용 차감 공헌이익 |
|---|---:|---:|---:|---:|---:|---:|
| 보기만 재미있는 콘텐츠 | 100,000 | 0.1% | 100 | 30원 | 3,000원 | 0원 |
| 구매 관심이 연결되는 콘텐츠 | 10,000 | 2% | 200 | 60원 | 12,000원 | 9,000원 |
| 노출 적지만 관련성 높은 콘텐츠 | 3,000 | 2% | 60 | 60원 | 3,600원 | 600원 |

손익분기 조회 = 비용/(방문율×EPC). 위 가정에서 0.1%×30원이면 100,000조회, 2%×60원이면 2,500조회 필요. 41조회와 후자의 가정을 적용하면 기대 수수료 약 49원. 작은 표본과 가정의 계산으로 실제 매출을 단정할 수 없지만, 현재 노출 수준에서 댓글만 다듬는 것으로 경제성이 해결되기는 어려움을 보여준다.

사용자 시간이 10분에서 3분이면 기회비용 1,750원 절감. 매번 5개 후보를 읽게 만들거나 반복 리젝/상품 검색을 시키는 기능은 API 비용이 싸도 비싼 자동화가 될 수 있다.

## 권장 검증 순서

1. 기존 원본 10개 안팎을 고정한 오프라인 비교 세트: 기존 카피 / 새 지침 / 새 지침+장면 설명. 강사 GPT 출력은 확보된 사례만 기준으로 활용. 같은 이미지·원문 입력 조건 통제.
2. 사용자 블라인드 평가: 장면 정합성, 한국어 자연스러움, 특징 보존, 허구 여부. 이는 문구 선호 검증이며 조회/매출 증명이 아님.
3. 실제 발행은 서로 다른 원본을 상품군·미디어 유형별로 균형 배정. 한 번에 한 변경을 시험. 같은 상품 계정별 14일 규칙과 계정 간 시차 준수. 10~20건은 운영 파일럿이며 통계적 승리 선언 기준 아님.
4. 24/72h 동일 시점 비교 및 충분한 수익 확정 기간 대기. 최고값만 보지 말고 중앙값·총 확정 수수료·상위 한 건 제외 성과·사용자 소요시간도 함께 평가. 소수 바이럴로 생기는 분산을 유지해서 보고.
