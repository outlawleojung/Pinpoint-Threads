# 프로젝트 비전 & 핵심 인식

## 🔴 이 프로젝트는 "자동 발행 봇"이 아니다

Pinpoint-Threads는 **AI 콘텐츠 인텔리전스 시스템**이다. 자동화는 수단일 뿐, 핵심 가치는 다음에 있다:

### 핵심 가치: 터진 콘텐츠의 패턴 재생산

- 이미 터진 게시글을 수집하고, **"왜 터졌는가"를 구조적으로 분석**해서, 그 패턴을 새 콘텐츠로 재생산한다
- 단순 복붙이나 리라이팅이 아니라, 성공 요인(톤, 구조, 소재 선택, 타이밍)을 추출하고 재조합하는 것
- 이 분석의 정밀도가 곧 콘텐츠 품질이고, 콘텐츠 품질이 곧 수익이다

### 수익 구조: 롱테일 게임

- 어필리에이트 수익은 "평균 전환율 × 노출"이 아니다
- **터진 게시글 하나가 10만~100만원 수익**을 만든다
- 매일 꾸준히 품질 높은 콘텐츠를 쏘다가 → 하나 터지면 → 그 하나가 월 매출을 만드는 구조
- AI가 매일 "터질 확률이 높은" 콘텐츠를 생산하는 것이 이 시스템의 존재 이유

### 피드백 루프: 돌수록 정밀해진다

```
Source Collector (터진 글 수집)
    → Content Classifier (왜 터졌는지 분석)
    → Copywriter (패턴 기반 새 콘텐츠 생성)
    → Publisher (발행)
    → Performance Collector (성과 회수)
    → 다시 학습 데이터로 축적
```

- 이 루프가 돌수록 AI의 트렌드 파악 정밀도가 올라간다
- 데이터 임계량 도달 시 RAG 자동 전환 (ADR 005)으로 더 정교한 패턴 매칭

## 가장 중요한 작업: 프롬프트 튜닝

프롬프트 품질이 수익을 직접 결정한다. 특히:

- **Copywriter**: 터진 글의 패턴을 얼마나 정확히 재현하는가
- **Content Classifier**: "왜 터졌는지"를 표면적으로 읽지 않고 구조적으로 분해하는가
- **Vision Verifier**: 이미지-상품 매칭의 정확도

AI 모듈에 데이터를 넣어줘도, AI가 그것을 표면적으로만 읽으면 평범한 콘텐츠만 나온다. 프롬프트가 AI를 "왜"에 집중시켜야 한다.

## 🔴 2026-08-31 재정립: 인간 큐레이션 + AI 재창조 모델

원래 vision은 "터진 콘텐츠 자동 수집 → 패턴 학습 → 재생산" 이었으나, 2026-08-31 세션에서 근본 재검토 결과 **주력 모델을 전환**:

### 주력: 수동 URL 시딩 + 완전 재창조

**사용자가 Threads · TikTok · 샤오홍슈 · Instagram 앱을 쓰다가 눈에 띄는 게시글 URL을 텔레그램 봇에 던지면, 시스템이 그 원본을 파싱·번역·상품 매칭 후 계정별 페르소나로 완전히 다른 카피를 생성해 5개 계정에서 자동 발행.**

### 왜 이 방식이 우월한가

1. **인간 큐레이션 = 최상의 필터** — 사용자가 앱에서 이미 판단 완료한 콘텐츠만 시스템 진입 → 잡음 0
2. **선행 트렌드 즉시 활용** — 미국 TikTok·중국 샤오홍슈에서 뜬 상품을 한국 도착 전에 콘텐츠화
3. **글로벌 아비트라지** — 원본 언어(영·중·일) 무관, 한국 정서로 완전 재작성
4. **개발 스코프 대폭 축소** — 30계정 자동 폴링 인프라 불필요
5. **낮은 유지비** — Apify 대량 폴링 대신 단건 URL fetch만

### 원칙: 직역 금지 · 계정별 완전 재창조

- 원본은 **소재·훅 참고용**. 문장 그대로 옮기지 않음.
- 각 계정은 다른 페르소나·컨셉. 같은 원본이라도 계정마다 다른 카피 생성.
- 30-40대 주부만 타겟 X. 계정별 타겟 다양.
- 한국 정서 · 어감 · 유행어 반영. AI는 번역이 아니라 재창조 담당.

### 부가: Threads 벤치마크 소규모 병행

원래 계획했던 벤치마크 자동 수집(Apify 30계정 폴링)은:
- **스코프 축소**: 시드 5개 소규모 유지 (사용자 손 놓아도 완전 정지 방지)
- **역할 재정의**: 카피 학습용 RAG 소스로만 활용

### 개발 우선순위 재편 (Task #6 시리즈 신규)

- **6a**: URL Ingester 프레임워크 + 텔레그램 봇 확장
- **6b**: Threads URL Adapter
- **6c**: 다국어·계정별 페르소나 이식 Copywriter 확장 ★핵심
- **6d**: 계정별 페르소나 정의·관리 UI
- **6e/f/g**: TikTok · 샤오홍슈 · Instagram Adapter 순차

## 근본 전략: 창작이 아니라 역설계

이 프로젝트는 새로운 콘텐츠를 창작해서 시장에 테스트하는 것이 **아니다.**

- **이미 터진 게시글** (좋아요·댓글 수만 개)을 가져온다
- **이미 반응이 검증된 상품**을 가져다 쓴다
- AI는 이것들을 분석해서:
  - 터진 글의 패턴 (구조, 훅, 톤, 길이, CTA)
  - 그 시기의 트렌드 (계절, 유행, 많이 다뤄지는 브랜드/카테고리)
  - 상품군별 반응 패턴
- 이 모든 분석 결과를 DB에 저장하고 학습한다
- 그리고 이 학습된 패턴 + 현재 트렌드에 맞는 콘텐츠를 재생산한다

**리스크 최소화 구조**: 상품 선정도, 콘텐츠 포맷도, 소재도 전부 "이미 증명된 것"의 역설계. 우리가 테스터가 되는 것이 아니라, 시장이 이미 검증한 것을 활용한다.

## 검증된 전제: AI 생성 콘텐츠는 이미 먹힌다

- 스레드 수익화 강의에서 강사가 만든 GPT 게시글 생성기로 콘텐츠를 만들어 실제 발행·수익화한 경험이 있음
- 즉, "AI가 만든 글이 Threads에서 반응을 얻을 수 있는가?"는 이미 검증된 사실
- 남은 과제는 AI 콘텐츠 자체의 가능성이 아니라, **우리 프롬프트가 그 수준 이상을 내느냐** — 이건 강의 지식 추출 + 프롬프트 튜닝으로 해결 가능한 기술 영역

## 시장 검증: 같은 모델로 실 수익 인증 존재

- 스레드 수익화 강의 수강생들이 같은 방식(AI 생성 콘텐츠 + Threads + 쿠팡 파트너스)으로 실 수익 인증
- 월 500만원, 1000만원, 2000만원 수준의 쿠팡 파트너스 수익 인증 사례 다수 존재
- 이들은 수동 운영 — 우리 시스템은 이 수동 과정을 자동화 + AI 분석 고도화
- 즉, 비즈니스 모델 자체는 검증됨. 우리가 만드는 것은 이 검증된 모델의 자동화·스케일 도구

## 금지 사항

- 이 프로젝트를 일반적인 어필리에이트 마케팅 자동화 프레임으로 평가하지 말 것
- 설계 문서를 무시하고 업계 평균 지표로 수익을 추정하지 말 것
- "자동화"에 초점을 맞추지 말 것 — AI 콘텐츠 품질이 핵심이다

## 🔴 현재 상태 vs 목표 (현실 인지)

프레임과 실제 구현 사이 갭이 크다. 무엇이 되어 있고 무엇이 안 되어 있는지 명확히 구분한다.

### 현재 코드 (Phase 3 완료)

**되는 것 (검증됨):**
- 소스 이미지 · 텍스트 입력 → 소비재 적합성 판정 (얕은 필터)
- 쿠팡 상품 검색 · Vision 매칭 · 딥링크 생성
- 짧은 후킹 문장 본문 카피 생성
- 감초 톤 고정 댓글 생성 + 공정위 문구 강제
- 4가지 실전 리플라이 양식 파일 (지금은 사용 안 함)
- Cloudinary 미디어 미러 업로드
- 텔레그램 승인 UI + 상태 머신

**아직 안 되는 것 (미구현):**
- viralFactors 자동 분석 (왜 터졌는지 구조 분해)
- 트렌드 시계열 감지 (계절·유행 카테고리 자동 추적)
- 벤치마크 DB 축적 (BenchmarkPost 스키마만 정의, 실 데이터 0)
- RAG few-shot 검색 (Voyage AI 미통합)
- 패턴 재생산 프롬프트 (지금은 지침만, 벤치마크 참조 없음)
- 다계정 발행 스케줄링 · 성과 회수 (Meta 승인 대기)
- 팔로우백 (Threads API 지원 안 함, 반자동/수동 결정 대기)

### 즉 지금 실체는

**"AI 콘텐츠 자동화 봇" 수준.** 컨텐츠 판정·매칭·카피·발행 준비는 됨. 하지만 "인텔리전스"의 핵심인 **패턴 분석·트렌드 학습·재생산**은 아직 없음.

### 완전한 "인텔리전스"까지의 로드맵

| 단계 | 필요 작업 | 예상 Phase |
|---|---|---|
| 1. 발행 e2e | Meta 승인 · Publisher · OAuth 흐름 | Phase 4 |
| 2. 벤치마크 데이터 축적 | Source Collector (수동 시드 + Apify + 성과 회수) | Phase 4~5 |
| 3. 트렌드 · viralFactors 분석 | 새 AI 노드 · BenchmarkPost 확장 필드 활용 | Phase 5 |
| 4. RAG 자동 전환 | Voyage 임베딩 · pgvector 검색 · Copywriter RAG 모드 | Phase 5~6 |
| 5. 완전한 피드백 루프 | 발행 → 성과 → 벤치마크 승격 → 다음 카피 개선 | Phase 6+ |

**즉 "인텔리전스 시스템"은 목표 프레임이지 현 상태가 아님.** 지금은 그 방향으로 가는 초기 단계.

### 가능 · 불가능 구분

**기술적으로 가능하고 우리가 만들 것:**
- Threads Graph API 발행 (텍스트 + 미디어 + 고정 댓글)
- 성과 회수 (좋아요 · 댓글 · 조회수 insights)
- 4~5계정 병렬 운영 (계정별 시차 · 페르소나 격리)
- 이미지 미세 가공 (Sharp)
- Cloudinary 미디어 호스팅
- 수동 시드 파이프라인

**기술적으로 가능하나 정책상 안 할 것:**
- 클로킹 (Meta ToS 위반)
- 비공식 API로 팔로우 자동화 (계정 정지 리스크)

**기술적으로 불가능 (Threads API 미지원):**
- 자동 팔로우/언팔로우
- 팔로워/팔로잉 목록 조회
- 특정 사용자 팔로우 여부 검증
- (Pipeline B 스하리는 이 제약 위에서 반자동/수동 설계)
