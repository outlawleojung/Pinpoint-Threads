## 핵심 결정 & 인식 변경

### 1. 프로젝트 정체성 재정의
- "자동 발행 봇"이 아니라 **AI 콘텐츠 인텔리전스 시스템**
- 핵심 가치: 터진 게시글의 "왜 터졌는가"를 AI가 분석·재생산
- 자동화는 수단, AI 콘텐츠 품질이 수익을 결정
- CLAUDE.md 첫 줄에 명시, vision.md에 상세 작성

### 2. 근본 전략: 창작이 아니라 역설계
- 새 콘텐츠를 창작해서 테스트하는 것이 아님
- 이미 터진 글, 이미 검증된 상품을 가져다 활용
- AI는 패턴 분석 + 트렌드 분석 (계절, 유행 브랜드/카테고리) + DB 저장 + 학습
- 리스크 최소화 구조: 시장이 이미 검증한 것을 역설계

### 3. 시장 검증 확인
- 같은 모델(AI 생성 + Threads + 쿠팡 파트너스)로 월 500만~2000만원 실 수익 인증 사례 다수 존재 (강의 수강 카페)
- 강의 강사가 만든 GPT 게시글 생성기 사용 경험 있음 → AI 콘텐츠 품질은 검증된 전제
- 수동 운영자들의 병목(시간/노동력)을 자동화로 해결 → 계정 수 스케일로 수익 증폭

### 4. 강의 지식 추출 파이프라인
- 네이버 카페 수익화 강의 영상 8~10개 (각 4~8시간)
- 방법: 잠잘 때 OBS 녹화 → Whisper 전사 → Claude 사담 필터링 + 알짜 추출 → 프로젝트 반영
- 하루 1개씩 ~10일 소요
- 문서: docs/05-data-collection/lecture-knowledge.md

### 5. 콘텐츠 대시보드 & 수동 재발행
- 모든 발행 이력 저장, 관리자 페이지에서 조회·재발행
- 과거 콘텐츠 골라서 → 원하는 계정에 재발행 가능
- Threads는 텍스트 기반이라 중복 콘텐츠/표절 문제 없음
- ADR 007 자동 재활용과 별개로 수동 경로 공존
- 문서: docs/02-architecture/content-dashboard.md

### 6. 데이터 수집 3-track 병행 전략
- Track 1: 자동 수집 (Source Collector) — 안티봇 리스크 있음
- Track 2: 수동 시드 (사용자가 Telegram에 URL 전달) — 항상 작동, 초기 주력
- Track 3: 내 계정 성과 회수 (Performance Collector) — Meta 승인 필요
- Track 1이 막혀도 Track 2가 살아있어 피드백 루프 유지
- 문서: docs/05-data-collection/strategy.md

### 7. BenchmarkPost 트렌드 분석 필드 추가
- brandNames, productCategory, seasonalTag, trendKeywords, viralFactors, collectedAt
- viralFactors: AI가 "왜 터졌는가" 분석 결과 (hook, tone, structure, CTA)
- 기존 스키마에 없던 핵심 필드들
