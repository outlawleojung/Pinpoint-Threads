# 2026-09-03 세션 인수인계

## 이 세션의 핵심

아침 트렌드 다이제스트에 정치·인물·남성템이 섞여 나온 것을 계기로 **"DB에 쌓인 벤치마크로 실제 콘텐츠를 자동 생산"** 이 목적임을 재확인. Pipeline A 쇼핑 자동 발행을 실 계정으로 반복 검증하며 계층별 버그를 하나씩 잡음. 결과적으로 **실 발행까지 e2e 성공** (열무김치 · minyoung.jung, 슬리퍼 · pikkseetem 등).

## 크론 정리 (세션 초반)

- **trend-poll: 6h interval → 07:00 KST 하루 1회** (하루치 재수집 낭비 제거)
- BullMQ 스케줄러 중복 정리 (구 시각 잔재 제거): sharing-collect·sharing-publish·shopping-publish
- 현재 크론 7개 각 1건 (07:00 poll · 07:30 metrics · 08:00 digest+sharing-collect · 08:30 search · 09:00 sharing-publish+shopping-publish)

## 핵심 설계 결정

### 1. Threads 비디오 추출 (shortcode 매칭)
- 실 DOM 조사: `<article>` 태그 없음 · video 9개 중 target 1개 · 8개는 추천글
- 각 `<video>` 의 부모 `[role="link"]` 의 `a[href*="/post/"]` permalink 에서 **URL shortcode 매칭** → target 게시글 비디오만 정확 추출
- `pickBestMp4s` 는 1개만 반환 (다중 비디오 게시글 드묾)
- 어댑터: Apify 가 mp4 주면 그대로 · 아니면 비디오 게시글일 때만 Playwright 보강

### 2. 매칭 실패 → 텔레그램 URL 답장 흐름 (신규)
- 자동 매칭 vision-failed 시 **원본 미디어·텍스트 대기 카드** 텔레그램 발송
- Redis `pending-match:{msgId}` 저장 (TTL 24h) · **앨범은 전체 메시지 ID 저장** (답장 매칭)
- 사용자가 대기 카드에 답장으로 쿠팡·무신사·네이버 URL 던짐 → 하이브리드 재실행 → 승인 카드
- 네이버·무신사 지원 추가 (CommerceChannel enum NAVER)

### 3. 쿠팡 딥링크 처리
- **축약 URL (`/products/id`, itemId 없음) 은 쿠팡 딥링크 API 변환 거부** (400 url convert failed)
- **완성된 딥링크 (`link.coupang.com/a/...`) 는 재생성 없이 그대로 사용**
- 사용자 워크플로: 쿠팡 상품 → 공유 → 파트너스 링크 만들어서 답장

### 4. 채널별 공정위 문구
- 쿠팡: "쿠팡 파트너스 활동의 일환으로..."
- 무신사: "무신사 큐레이터 활동의 일환으로..."
- 네이버: "네이버 쇼핑 제휴 활동의 일환으로..."

## 상품 다양성 이슈 (미해결·구조적)

- 자동 매칭은 vision-failed 확률 높음 → 실질 발행은 **하이브리드 URL 붙은 벤치마크만** 성공

## 후반부 핵심 전환: 상품명 기반 수동 발행 (docs/08-decisions/manual-shopping-flow.md)

### 발견한 근본 문제
- **텔레그램이 쿠팡 링크(link.coupang.com·coupang.com) 전송을 차단** (타이핑해도 · 봇에 안 옴).
  → 대기 카드 답장·회신코드+URL 방식 다 무력화.
- **상품번호만으론 딥링크 불가** (itemId+vendorItemId 필요 · 추출 불가).
- **자동 Product Matcher 오매칭 잦음** (vision-failed) → 결국 전부 수동 하이브리드로 흘러 손 많이 감.

### 해결: 상품명(텍스트)으로 발행
- 상품명은 링크 아니라 텔레그램 안 막음.
- 쿠팡 파트너스 **검색 API** 에 상품명 → 정확한 상품 top → productUrl(itemId 포함) → **딥링크 생성 성공** (실측).
- `RunPipelineAInput.productNameHint` + `matchProduct.trustKeyword`: 상품명 지정 시 Vision 미달이라도 best 후보 채택.
- `InboundLink.manualProductName` 필드 (migration) · 자동 크론도 재사용.
- Bot: "벤치마크 URL + 상품명" 또는 "회신코드 + 상품명" → 상품명 검색 발행.
- **Threads /share/ 단축 URL 해석** (Playwright · fetch 는 JS 렌더라 안 됨).
- 쿠팡 상품 제목 추출 (Playwright · Access Denied 재시도) → 카피에 특징 반영.

### 비용 절감 (크레딧 소진 계기)
- **trustKeyword 모드 Vision 완전 스킵** (최대 비용 요인) · 후보 5→3 · fact-check 2→1 · reply Haiku.
