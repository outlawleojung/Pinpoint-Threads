### 2) OAuth 흐름 구현 (Task #17)

**만든 것:**
- [src/infra/threads-client.ts](../../src/infra/threads-client.ts) — 코드↔토큰 교환, refresh, 프로필 조회

- [src/modules/shared/publisher/oauth/routes.ts](../../src/modules/shared/publisher/oauth/routes.ts) — Fastify 라우트 4개

**노출된 URL:**
- `GET /oauth/threads/start` — Meta authorize로 리다이렉트 (state CSRF)
- `GET /oauth/threads/callback` — 코드 수신 → short→long 토큰 교환 → 프로필 → DB
- `GET /oauth/threads/accounts` — 연결 계정 목록 · refresh · delete
- `POST /oauth/threads/accounts/:id/refresh|delete`

**HTTPS 강제 이슈:** Meta는 콜백 URL에 HTTPS만 허용 → localhost 직접 사용 불가.
→ 해결: GitHub Pages(`callback.html`)에 브리지 JS 배치, `?code=...&state=...` 를 그대로 `localhost:3000`로 릴레이.
→ `.env`의 `META_REDIRECT_URI`는 GitHub Pages URL로 설정.

### 3) Publisher 실 구현 (Task #18)

**ThreadsClient 실 구현:**
- `createContainer` — POST `/v1.0/me/threads` (TEXT/IMAGE/VIDEO/CAROUSEL 지원)
- `waitForContainerReady` — 2초 폴링 · 60초 타임아웃
- `publishContainer` — POST `/v1.0/me/threads_publish`
- `publish()` — 미디어 수에 따라 자동 분기 (0=text, 1=image, 2+=carousel)
- `reply()` — `reply_to_id` 지정 텍스트 컨테이너 → publish

**Publisher 모듈 (오케스트레이션):**
- `PublishInput { postId }` — Post 레코드 기반
- 계정 활성 · 토큰 유효 검증
- 7일 이내 만료면 자동 refresh
- 상태 전이: APPROVED → PUBLISHING → PUBLISHED / FAILED
- 메인 발행 성공 후 고정 댓글 실패 시: 메인은 살아있으므로 에러 로그만, 예외 전파 X
- `PublisherError` 커스텀 예외 (ACCOUNT_INACTIVE, TOKEN_MISSING, INVALID_STATE, API_ERROR)

**미테스트 항목:**
- 실 Meta API 호출은 아직 안 함 (Task #19 사용자 요청으로 보류)
- 첫 실 발행은 다음 세션에서 짧은 텍스트로 조심스럽게 진행 예정

## 세션 최종 — Vision 2-Lane 아키텍처 확정

Task #5 시리즈 스코프를 정하다가 사용자님 통찰이 연속으로 vision을 upgrade:

1. "30개 시드가 안 터지면?" → 고정 폴링의 취약점 인지
2. "다른 플랫폼 소스는?" → TikTok · 샤오홍슈 · Instagram 확장
3. "트렌드는 매번 달라진다" → 능동 트렌드 감지 필요
4. "내가 URL 던지면?" → 수동 큐레이션이 최고 필터
5. **"내가 일 안 해도 멈추지 않아야 한다"** → 완전 자율 시스템 필수

**최종 결론: 2-Lane 아키텍처**

- **Lane 1 (Manual)**: 사용자 URL → 즉시 처리
- **Lane 2 (Autonomous)**: 트렌드 시그널 24/7 감지 → 능동 검색 → 자동 인제스트 → 승인 대기 큐

두 Lane은 같은 하류(파싱·번역·상품매칭·계정별 페르소나 재창조·발행)로 수렴. 사용자 노동은 옵션(승인만), 시스템은 자율 운영.
