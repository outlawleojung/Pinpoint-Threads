# 콘텐츠 대시보드 & 수동 재발행

## 핵심 아이디어

모든 발행 콘텐츠의 이력을 저장하고, 관리자 페이지에서:
1. **어떤 콘텐츠를 / 언제 / 어떤 계정에 올렸는지** 한눈에 조회
2. **과거 콘텐츠를 골라서 → 원하는 계정에 재발행** 지시 가능

## 왜 필요한가

- 반응 좋았던 콘텐츠는 다시 써먹을 수 있다
- Threads는 텍스트 기반 → 중복 콘텐츠/표절 감지가 사실상 없음
- ADR 007의 자동 재활용과 별개로, **관리자가 직접 판단하고 선택**하는 수동 경로가 필요
- 자동화만으로는 못 잡는 감각적 판단 ("이거 지금 다시 올리면 터지겠다")을 사람이 개입

## 기능 명세 (초안)

### 콘텐츠 조회
- 전체 발행 이력 리스트 (계정별 / 날짜별 / 성과순 필터)
- 각 게시글: 본문 프리뷰, 미디어 썸네일, 발행 계정, 발행 시각, 성과 지표
- 성과 지표: 좋아요, 댓글, 공유, engagementScore

### 재발행
- 콘텐츠 선택 → 발행 대상 계정 선택 → 재발행 큐에 추가
- 재발행 시 옵션:
  - 원본 그대로 발행
  - AI가 톤/표현만 살짝 변형 (계정 페르소나에 맞게)
  - 미디어 교체 (같은 상품, 다른 이미지)
- 계정별 14일 동일 상품 금지 규칙은 자동 체크

### 인사이트
- 콘텐츠별 재발행 횟수 & 각 회차 성과 비교
- "재발행해도 성과 유지되는 콘텐츠" = Evergreen 후보 자동 태깅
- 시간대별/요일별 성과 히트맵

## 구현 시기

- ADR 007에서는 대시보드를 N≥20 이후로 잡았으나, **운영 도구로서의 대시보드는 더 일찍 필요**
- Phase 4 (Publisher 완성) 이후, 실 발행 데이터가 쌓이기 시작하면 바로 착수 가능
- 초기에는 Telegram 봇 UI로 간이 조회/재발행도 가능 (웹 대시보드 전 단계)

## 기술 고려사항

- 발행 이력 저장: 이미 Prisma Post 모델에 기본 구조 있음, 확장 필요
- 프론트엔드: 경량 웹 UI (관리자 1명 전용이므로 심플하게)
- 재발행 큐: 기존 BullMQ 활용, delayed job으로 시차 적용

## ADR 007과의 관계

- ADR 007 = **자동 재활용** (Planner가 알아서 배치)
- 이 대시보드 = **수동 재발행** (관리자가 직접 선택)
- 두 경로가 공존: 평소엔 자동, 필요 시 수동 개입
